# From Raw Data to Business Decisions: My End-to-End Data Analytics Journey

Data analytics is much more than creating charts or writing Python code. A useful analysis starts with raw information and ends with a decision that a business can understand and act upon.

During my Growfinix Data Analytics Internship, I worked on projects that allowed me to explore different stages of this process.

## 1. Data Cleaning Comes Before Analysis

My first project involved exploratory data analysis on a real-estate dataset.

The dataset contained missing values, duplicate records, inconsistent values and outliers. Using Python and Pandas, I cleaned the dataset before performing the analysis.

One of the most important lessons from this project was that analytical results are only as reliable as the underlying data.

## 2. Data Can Be Collected Automatically

The next stage involved automated data extraction.

Using Python, Requests and BeautifulSoup, I explored how publicly available web information can be transformed into structured datasets.

Web data often contains unnecessary symbols and inconsistent formatting, so the extracted information also required cleaning before analysis.

This project helped me understand the relationship between data collection and data preparation.

## 3. Analytics Must Be Communicated

Analysing information is useful only when the results can be understood by decision makers.

For this reason, I created an interactive Tour Enquiry Dashboard using Streamlit and Plotly.

The dashboard displayed metrics such as total enquiries, booking conversions, popular destinations, peak enquiry times, customer locations and lead sources.

Interactive filtering allowed users to explore different parts of the dataset without modifying the underlying Python code.

## 4. SQL Remains Essential for Analytics

Modern organisations frequently store data across multiple relational database tables.

I used SQL and SQLite to analyse information distributed across user, property and booking tables.

The project included JOIN operations, aggregations, CTEs, window functions and conditional queries.

The query results were then imported directly into Pandas DataFrames. This demonstrated how SQL and Python complement each other in practical analytics workflows.

## 5. Higher Numbers Do Not Always Mean Better Results

The final project focused on A/B testing.

Two interface variants were compared based on conversion rate. Although one variant produced a higher conversion rate, statistical testing was required before deciding whether the difference represented a genuine improvement.

Using SciPy and Statsmodels, I analysed conversion rates, absolute lift, relative lift, p-value, confidence intervals and statistical significance.

The experiment demonstrated an important analytical principle: a numerical difference does not automatically mean a statistically reliable difference.

## The Complete Analytics Lifecycle

Together, these projects helped me understand the following workflow:

Data Collection -> Data Cleaning -> Exploratory Analysis -> SQL Analysis -> Visualization -> Statistical Testing -> Business Insights -> Decision Making

## Technologies Used

Python, Pandas, Matplotlib, Seaborn, BeautifulSoup, Requests, SQL, SQLite, Streamlit, Plotly, SciPy and Statsmodels.

## Conclusion

The most valuable outcome of these projects was not simply learning individual libraries. It was understanding how those technologies connect.

Python can clean data. SQL can retrieve it. Visualization can communicate it. Statistics can validate it.

But the final goal of analytics is to transform data into reliable information that supports better decisions.

This internship provided me with practical exposure to that complete process.
